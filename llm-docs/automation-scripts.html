Darkflow Automation Scripts

Darkflow aliases and triggers now support text scripts with if, elseif, and else branches, while preserving the existing step-based automation system.

What Changed

New script step

Aliases and triggers can add a Run script step in the settings automation editor.

Branching logic

Scripts can choose different actions with if, elseif, else, and end.

Same automation engine

Script actions reuse the existing command, variable, alias, trigger, and sound execution paths.

Backward compatible

Existing aliases, triggers, imports, exports, and visual steps continue to work unchanged.

Script Syntax

Scripts are line-oriented. Blank lines and lines starting with # are ignored.

if $hp < 50
  send drink healing potion
elseif %1 matches /orc|goblin/i
  run_alias assist %1
else
  show No condition matched.
end

Supported Control Flow

  • if <condition>
  • elseif <condition>
  • else
  • end
  • Nested conditionals are supported up to five levels deep.

Supported Actions

Action Example Behavior
send send kill %1 Sends a command to the MUD.
show show Target is %1 Prints a local client message.
set set $target = %1 Writes a persistent alias variable for the active server scope.
run_alias run_alias assist %1 Runs an existing alias, preserving recursion and depth protection.
enable_alias, disable_alias, toggle_alias disable_alias heal Changes an alias by trigger text.
enable_trigger, disable_trigger, toggle_trigger toggle_trigger You are hungry. Changes a trigger by pattern text.
play_sound play_sound alert/warning 50 Plays a known Darkflow sound. Volume can be 0-1 or 0-100.

Conditions

Conditions use the same template context as existing automation: $variables, %0, and %1 through %9. Regex triggers expose captures as %1 onward, while simple aliases use %0 for the whole remainder after the alias.

Condition Example
Exists / empty exists $target, not_empty %1
String equality $stance == defensive, %1 != goblin
String contains %1 contains orc, $mode not_contains quiet
Regex %1 matches /orc|goblin/i
Numeric comparison $hp < 50, { $hp / $maxhp * 100 } <= 30
The implementation intentionally does not use JavaScript eval. It parses a small, explicit scripting language to keep player settings safe.

How It Is Built

  • automation-script-core.mjs parses scripts and evaluates conditions.
  • automation-executor.js executes script steps through the existing automation step pipeline.
  • alias-manager.js and trigger-manager.js preserve script steps and report script diagnostics.
  • settings-automation.js adds the Run script editor and preview support.
  • Tests cover parsing, malformed control flow, condition evaluation, alias scripts, trigger scripts, and variable flow.
